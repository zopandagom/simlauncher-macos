# 개발 계획

## 목표
- 누구에게: iPhone·iPad 가 없어 개발 중인 iOS 앱을 테스트하지 못하는 인원 (비개발자 포함). 공개 레포로 열어, 어느 회사든 자기 인프라(빌드 저장소)에 맞춰 쓸 수 있게 한다
- 무엇을: Mac 만 있으면 iOS 시뮬레이터를 띄우고 iOS 앱 빌드를 설치·실행해 테스트할 수 있게 한다
- 참고: 카카오페이 [멀티버스](https://tech.kakaopay.com/post/multiverse/) (가상 기기 + 앱 센터 + 테스트 편의 기능)
- 범위: iOS 시뮬레이터 먼저(0~6단계, 1.0.0). Android 에뮬레이터는 7단계에서 iOS 와 같은 기능(기기 목록·켜기·끄기·만들기·삭제·초기화, apk 설치(파일·URL·카탈로그)·실행·딥링크, 스크린샷·녹화, 여러 기기 설치)을 더해 1.1.0 으로 낸다 (진행 중)
- 화면 언어: 한국어 먼저. 문자열은 처음부터 String Catalog(`Localizable.xcstrings`)에 둬서 영어를 나중에 추가한다
- 라이선스: MIT
- 출시 목표: 1.0.0 — Developer ID 서명·공증 dmg 를 GitHub Releases 에 올린다 (로드맵 6단계). 2026-10-27 에 [1.0.0](https://github.com/zopandagom/simlauncher-macos/releases/tag/1.0.0) 을 게시했다

## 핵심 기능 (MVP)
| 영역 | 기능 | 기술 메모 |
|---|---|---|
| 사용 환경 | Xcode·시뮬레이터 런타임 확인, 없으면 안내. iOS 런타임은 앱에서 설치 | `xcode-select -p`(물려받은 `DEVELOPER_DIR` 를 지운 환경), `simctl runtime list -j`(런타임 디스크 이미지와 상태), `xcodebuild -downloadPlatform iOS`. 기본 iOS 런타임은 고른 Xcode 의 iOS Simulator SDK 버전이고(SDK 의 `SDKSettings.plist`·`SystemVersion.plist` 를 읽는다), 같은 major.minor 의 iOS 이미지(patch·build 는 보지 않는다)가 Ready 면 설치됨, 받은 뒤 확인·마운트 중이면 준비 중, Unusable 이면 쓸 수 없음으로 보고, 삭제 중이거나 상태를 알 수 없는 이미지는 없는 것으로 본다. 설치는 사용자가 누를 때만 버전을 지정하지 않는 `-downloadPlatform iOS` 로 하고, 진행률(준비 → 내려받기 퍼센트·바이트 → 설치)을 보이고 취소할 수 있다(설치 단계는 취소하지 않는다). 60초 동안 진행이 없으면 연결 확인 안내를 보이되 실패로 바꾸지 않고, 결과(설치함·이미 있음·실패·취소)와 관계없이 끝나면 환경과 런타임을 다시 확인한다. 다른 iOS 버전 목록은 네트워크 없이 얻는 CLI 명령이 없어 제공하지 않는다. xcode-select 가 Xcode 를 가리키지 않으면(Command Line Tools·없음·깨진 경로) `/Applications` 맨 위의 Xcode 번들(Info.plist 의 식별자 `com.apple.dt.Xcode`·버전) 중 가장 높은 버전을 골라 `DEVELOPER_DIR` 를 지정해 실행한다 (사용자에게 `xcode-select -s` 를 시키지 않는다). 이렇게 고른 Xcode 를 `simctl`·`xcodebuild` 가 함께 쓰고, 쓸 Xcode 가 없으면 `simctl` 을 실행하지 않는다 (ARCHITECTURE §4). 준비 상태는 고른 Xcode 안의 `xcodebuild -checkFirstLaunchStatus`·`-license check` 로 확인한다 (`/usr/bin/xcodebuild` shim 은 쓰지 않는다). Xcode 는 App Store 페이지를 열고, 라이선스 동의·첫 실행 준비는 "Xcode 열기"(관리자 암호 필요)로 단계별 안내 (`Setup` Feature. 단계는 Xcode 설치 → 라이선스 동의 → 첫 실행 준비 → iOS 시뮬레이터 설치이고, iOS 런타임은 Xcode 가 준비된 뒤에만 확인한다. 앱 시작 때 확인해 메인 창 사이드바의 iOS 칸에 Xcode 가 미준비면 Setup, 준비되면(기본 iOS 가 없어도) 기기 목록. 단계마다 "다시 확인", 앱으로 돌아오면 자동 확인(설치 중에는 확인·기기 목록 이동을 막는다). 기기 목록 툴바 "개발 환경", iOS 런타임 없음·만들 수 있는 기기 종류 없음 화면의 설치 버튼, 목록 읽기 실패 화면의 "개발 환경 열기"로 다시 연다. 설치 중 앱을 끝내면 준비·내려받기 중이면 확인을 받아 설치를 멈추고, 설치 단계이거나 이미 멈추는 중이면 묻지 않고 끝나기를 기다린 뒤 앱을 끝낸다) |
| Android 환경 | 메인 창 사이드바의 Android 화면에서 Android SDK 도구(platform-tools·emulator·시스템 이미지)를 확인하고, 없으면 앱에서 설치 (Android Studio·Java 없이). SDK 위치는 기본 `~/Library/Android/sdk` 이고 설정 창에서 다른 폴더를 고를 수 있다 | `AndroidSDK` Client 가 SDK 위치의 파일만 읽어(네트워크·명령 없음, adb·emulator 를 실행하지 않는다) 구성 요소마다 설치됨(실행 파일·`system.img` 와 실행 권한)·없음·쓸 수 없음을 정한다 (Core `AndroidSDKStatus`, package.xml 은 보지 않는다). "Android 도구 설치" 를 누를 때만 Google 저장소 XML(`repository2-3.xml`·`sys-img/google_apis/sys-img2-3.xml`)을 받아(Download Client) 호스트 arch·stable 채널의 platform-tools·emulator 와 `google_apis` 시스템 이미지 중 가장 높은 숫자 API(emulator 의존을 만족하는 것)를 고르고 (Core `AndroidSDKSelection`), 없는 구성 요소만 설치한다. 설치 전에 그 패키지들이 쓰는 라이선스 원문을 시트로 보이고 동의를 받는다. 동의는 원문의 지문(SHA-256)으로 앱 설정(`Preferences` Client, 키 `AcceptedAndroidLicenses`)에만 기록하고 같은 원문은 다시 묻지 않는다. Android Studio·sdkmanager·Gradle 은 SimLauncher 의 동의 기록을 보지 않는다: 같은 SDK 로 Studio 에서 다른 패키지를 설치하거나 Gradle 이 빠진 패키지를 받을 때는 그쪽에서 따로 라이선스에 동의해야 한다 (Studio 의 SDK Manager 또는 `sdkmanager --licenses`). 설치는 패키지마다 받기(진행률·취소) → 크기·sha1 확인 → zipinfo 목록 검사 → SDK 안 스테이징 폴더에 `/usr/bin/unzip` 으로 풀기(ditto 는 Zip64 시스템 이미지를 풀지 못한다, 실측) → 푼 트리 검사 → 최종 경로로 덮어쓰지 않는 이름 바꾸기(`RENAME_EXCL`) 이고, 패키지 번호·단계·바이트와 전체 진행률을 보인다. 받는 크기는 약 2.5 GB, 설치 후 약 7 GB 이고 받기 전에 두 볼륨(받기 임시 폴더·SDK)의 여유를 어림으로 비교한다. 취소하면 그 패키지의 받은 파일·스테이징을 지우고 앞서 끝난 패키지는 남는다(마무리 단계는 취소하지 않는다). 실패는 원인(받기·손상·형식·저장 공간·SDK 폴더·이미 있는 폴더)과 다음 할 일을 보이고, 끝나면 결과와 관계없이 다시 확인한다. 설치 중 앱을 끝내면 받기·확인·풀기 중이면 확인을 받아 취소하고, 마무리 단계면 그 패키지만 마치고 끝낸다. 설정 창의 "Android SDK 위치" 절은 빈 폴더나 SDK 폴더만 저장하고(다른 파일이 든 폴더는 거절), 고른 폴더가 없어지면 만들지 않고 안내한다. 키 `AndroidSDKPath` 는 관리자가 미리 넣거나 잠글 수 있다 ([CATALOG.md](CATALOG.md) 9절). package.xml 은 쓰지 않는다 (`AndroidSetup` Feature). 셋 다 설치되면 Android 칸은 기기 목록으로 넘어간다 (기기는 "Android 기기" 행) |
| Android 기기 | 메인 창 사이드바의 Android 칸에서 Android 도구가 갖춰지면 기기(AVD) 목록을 보이고, 기기를 켜기·끄기·만들기(이름·시스템 이미지·화면 모양)·삭제·초기화한다. Android Studio 가 만든 기기도 보인다. 목록에서 여러 기기를 고르고(⌘·⇧ 클릭) 툴바 "선택한 기기 켜기"로 함께 켜고, "선택한 기기에 앱 설치"로 함께 설치한다(여러 기기 설치 행) | `AndroidEmulator` Client 가 `~/.android/avd`(Android Studio 와 함께 쓴다)를 읽고 쓰며 SDK 의 emulator·adb 를 실행한다 (ARCHITECTURE §4 Android 기기 행). 목록은 기기마다 표시 이름·API·휴대전화/태블릿·상태(꺼짐·켜는 중·켜짐)를 보이고, 켤 수 없는 기기(이름에 영문·숫자·`. _ -` 밖의 문자, 기기 폴더·설정 파일을 읽지 못함, 지금 SDK 위치에 없는 시스템 이미지, 이 Mac 에서 못 도는 abi)는 "사용할 수 없음" 과 이유를 보인다(켜기·초기화는 막고 삭제는 된다). 켜기는 실행 직전에 파일로 다시 확인한 뒤 emulator 를 띄우고 부팅 완료(`sys.boot_completed`)까지 기다린다(처음 켤 때는 1분 안팎, 최대 10분). 앱이 켜는 동안은 끄기를 막는다(켜는 중에 끄면 다음 켜기가 끝나지 않을 수 있다, 실측. 초기화로 복구된다). 끄기는 `adb emu kill`(스냅샷을 저장해 다음 켜기가 수 초). 만들기는 표시 이름(한글 가능)을 받아 앱이 ASCII 기기 이름을 만들고, 지금 SDK 에 설치된 시스템 이미지와 화면 모양 셋(휴대전화·작은 휴대전화·태블릿, SDK 에 기기 정의가 없어 앱이 갖는다) 중에서 고르며, 이미 있는 기기 파일을 덮어쓰지 않는다. 삭제·초기화는 확인 대화상자를 거치고 켜진 기기는 거절한다. 초기화는 켜지 않고 사용자 데이터·스냅샷만 지운다(다음 켜기가 오래 걸린다). 함께 켜기는 iOS 와 같은 규칙이다(쓸 수 있고 꺼졌고 작업 없는 기기만 동시에 켜고, 실패가 있으면 결과를 알림 하나에 모은다). 녹화 중인 기기의 끄기·삭제·초기화는 "녹화를 먼저 멈추세요" 로 막는다(녹화 행). 앱을 끝내도 켜진 에뮬레이터는 묻지 않고 남는다(iOS 시뮬레이터와 같다). 에뮬레이터 창을 닫거나 Studio 에서 바꾼 것은 새로 고침·앱 활성화 때 반영하고, 앱 밖에서 켜는 중인 기기가 있으면 2초마다 다시 읽는다 (`AndroidDevices` Feature) |
| Android 앱 설치 | Android 기기 목록에서 켜진 기기 행의 "앱 설치" 메뉴 "파일에서 고르기…" 나 행에 끌어다 놓기로 로컬 .apk 하나를, "URL 에서…" 로 입력한 https 주소의 .apk 를, "카탈로그에서…" 로 등록 카탈로그의 Android 앱 버전을 받아 설치하고 바로 실행한다 (받는 동안 행에 진행률·취소). 행 "앱 실행…" 은 그 기기에 사용자가 설치한 앱 목록(패키지 이름)에서 골라 실행하고, "링크 열기…" 는 앱 스킴 링크나 웹 주소를 그 기기에서 연다. 꺼진·켜는 중·쓸 수 없는 기기에서는 셋 다 막힌다(켜고 설치하지 않는다). 목록에서 여러 기기를 고르면 툴바 "선택한 기기에 앱 설치"(파일에서 고르기… / URL 에서… / 카탈로그에서…)로 함께 설치한다(여러 기기 설치 행) | `AndroidPackage` Client 가 apk 를 Mac 에 풀지 않고 검사한다: 확장자(.aab, 분할 묶음 .apks·.xapk·.apkm 은 거절), `zipinfo` 목록(손상·링크·경로 탈출·AndroidManifest.xml 하나), 서명 유무(v1 서명 파일 또는 v2+ 서명 블록), `unzip -p` 로 꺼낸 AndroidManifest.xml(바이너리 XML)의 패키지 이름·minSdk, `lib/<abi>/` 목록. Core 규칙이 켜진 기기의 ABI·API(`getprop`)와 대조해 맞지 않으면 이유와 함께 거절한다(ABI → API 순서). 설치는 `adb install -r -t -d --no-incremental`(덮어쓰기·테스트 전용 허용·이전 버전 허용(iOS 와 같이 덮어쓴다)·증분 설치 끔, 최대 10분)이고, 실패는 `INSTALL_FAILED_*` 코드로 원인과 다음 할 일(다른 서명의 같은 앱은 지우고 다시 설치 등)을 보인다. 실행은 기기가 찾은 launcher 화면(`cmd package resolve-activity`, 기기가 하나로 고르지 못하면 `query-activities` 의 첫 화면)을 `am start -n` 으로, 링크는 `am start -a android.intent.action.VIEW -d` 로 연다(원격 셸 인용). URL·카탈로그에서 받은 apk 는 `download.apk` 로 받아 같은 검사를 거치고(.aab·zip·웹 페이지는 내용으로 거절하고 이유를 알린다), 설치 명령이 끝나면 곧바로 지운다(여러 기기면 모든 기기의 흐름이 끝난 뒤 한 번). 받기·설치·실행·링크 열기는 앱을 끝낼 때 묻지 않는다 (`AndroidDevices` Feature, ARCHITECTURE §4 Android 앱 설치 행) |
| 시뮬레이터 | 기기 목록, 부팅·종료, 생성·삭제·초기화, Simulator 앱 띄우기. 목록에서 여러 기기를 고르고(⌘·⇧ 클릭) 툴바 "선택한 기기 켜기"로 함께 켠다 | `simctl list -j`, `boot`/`shutdown`, `create`/`delete`/`erase`, 개발자 디렉터리의 Simulator 앱(Xcode 27.1 은 DeviceHub)을 `open`. 함께 켜기는 고른 기기 중 쓸 수 있고 꺼졌고 다른 작업이 없는 기기만 동시에 켜고(켜져 있거나 작업 중인 기기는 알리지 않고 건너뛴다), 실패한 기기(또는 Simulator 앱 열기 실패)가 있으면 켜기를 시작한 기기의 결과를 알림 하나에 모은다. 켜기를 시작한 기기가 한 대면 행 "켜기"와 같다 |
| 앱 설치 | 기기 행 "앱 설치" 메뉴의 "파일에서 고르기…"로 로컬 .app(또는 .app 을 담은 zip)을 골라 설치. 드래그 앤 드롭 | `simctl install <기기> <.app>`. `AppBundle` Client 가 `Info.plist`(XML·바이너리)의 지원 플랫폼·`MinimumOSVersion` 과 실행 파일 Mach-O 헤더의 아키텍처를 읽고, Core 규칙이 대상 기기와 대조해 .ipa·Mac 앱·기기용·아키텍처·iOS 버전이 맞지 않는 빌드를 이유와 함께 거절. 꺼진 기기는 켜고, Simulator 앱을 열어(켜진 기기도) 설치하고 바로 실행. zip 은 `AppBundle` Client 가 임시 폴더에 `ditto -x -k` 로 풀어 맨 위 .app 하나를 쓰고(다른 맨 위 항목은 무시), 경로 탈출(`../`·절대 경로·밖을 가리키는 심볼릭 링크)은 거절하고, 풀기 전에 디스크 여유를 확인한다. 설치가 끝나면 임시 폴더를 지우고, 기기 목록 화면을 열 때 남은 폴더(앞선 실행이 남겼거나 지우지 못한 것)를 정리한다 |
| 앱 설치 | URL 의 .app(zip) 을 내려받아 설치 ("직접 설치"). 기기 행 "앱 설치" 메뉴의 "URL 에서…" 시트에 https 주소를 입력한다 | `Download` Client 가 URLSession 데이터 작업으로 `SimLauncher-Download-<UUID>` 임시 폴더에 받는다(진행률·취소, https 만·http 리다이렉트 거절, Content-Length 와 디스크 여유 비교·받다가 차면 지움, 받은 파일 이름은 고정). 입력은 Core `DownloadURL` 로 검사하고, 받는 동안 기기 행에 받은 바이트·진행 막대와 취소 버튼을 보인다. 받은 zip 은 로컬 zip 과 같은 `AppBundle` 경로로 풀고, 받은 파일은 풀기 직후(성공·실패 모두) 지운 뒤 로컬 설치와 같은 검사·설치·실행으로 이어진다. 받은 내용이 zip 이 아니면(로그인 페이지 HTML 등) 응답의 MIME 형식으로 이유를 골라 알리고, 받기 실패는 원인(HTTP 상태·연결·인증서·디스크 등)과 다음 할 일을 알린다. 남은 받기 폴더는 기기 목록 화면을 열 때 정리한다 |
| 빌드 카탈로그 | 설정에서 카탈로그 URL 을 등록하고, iOS·Android 기기 행 "앱 설치" 메뉴의 "카탈로그에서…" 시트의 앱·버전 목록에서 골라 설치 | 정적 `catalog.json` 하나 (규격: [CATALOG.md](CATALOG.md), schemaVersion 1·2 를 읽는다. 2 는 앱마다 `platform`(`ios`·`android`)이 있고 iOS 시트는 iOS 앱만, Android 시트는 Android 앱만 보인다. 1 은 모두 iOS 앱이다). 서버 없이 GitHub Releases·S3·사내 웹 서버 어디든 둘 수 있다. 설정 창(⌘,, `Settings` Feature. Android SDK 위치도 여기서 고른다, Android 환경 행)에서 등록할 때 한 번 받아 형식을 확인하고(통과해야 저장, 확인 중 취소·창 닫기는 저장 안 함), 같은 카탈로그(Core `DownloadURL.comparisonKey`)의 중복 등록을 막는다. 목록은 `Preferences` Client 가 UserDefaults 키 `CatalogURLs` 에 둔다. "카탈로그에서…" 시트는 열 때와 "새로 고침" 을 누를 때만 등록된 카탈로그를 동시에 받아 카탈로그마다 앱 목록이나 실패 이유를 보이고(한 카탈로그가 실패해도 나머지는 보인다), 앱을 고르면 버전 목록(최신순)에서 가장 새 버전을 고른다. 고른 버전의 빌드 URL 은 "URL 에서…" 와 같은 경로(받기 → 풀기 → 검사 → 설치 → 실행)로 설치하고, 받기·받은 파일 실패 중 빌드 주소·빌드 파일 쪽 원인은 카탈로그를 만든 사람에게 알리기(빌드가 없거나 접근이 거부되면 다른 버전 고르기도)를 다음 할 일로 알리고, 빌드 주소와 관계없는 원인(인터넷 연결·프록시 인증·서버 오류·시간 초과·끊김·저장 공간·임시 폴더)과 그 밖의 받은 zip·앱 검사 실패는 "URL 에서…" 와 같은 안내다 (docs/CATALOG.md 10절, `Launcher` Feature 의 `CatalogInstallModel`). Android 시트(`AndroidDevices` Feature 의 `AndroidDownloadInstallModel`)도 같은 규칙으로 받고 고르며, 고른 apk 는 "URL 에서…" 와 같은 경로로 설치한다 |
| 여러 기기 설치 | 목록에서 여러 기기를 고르고(⌘·⇧ 클릭) 툴바 "선택한 기기에 앱 설치"(파일에서 고르기… / URL 에서… / 카탈로그에서…)로 한 빌드를 기기마다 설치·실행. 행 메뉴·드래그 앤 드롭은 그 기기 하나에만 설치한다 | 시작할 때 고른 기기마다 지금 목록으로 판정해 없음·설치할 수 없는 상태·다른 작업 중인 기기는 이유와 함께 건너뛴다. 받기·풀기·검사는 한 번만 하고, 기기별 판정(iOS 버전 등) → 켜기 → 설치 → 실행은 동시에 돈다(상한 없음. 메모리가 모자란 Mac 에서는 설치·실행이 크게 느려진다, 2026-10-26 실측). 받는 동안 대상 행 모두에 같은 진행률과 취소가 보이고, 어느 행에서 취소하든 모두 멈춘다. 기기마다 끝나는 대로 그 행이 풀린다. 결과는 실패·건너뜀(또는 Simulator 앱 열기 실패)이 있을 때만 알림 하나에 기기별로 모으고(같은 결과는 한 줄로 묶는다), 받기·풀기·검사가 실패하면 한 기기 설치와 같은 원인 안내를 알림 하나로 보인다. 녹화 중인 기기에도 설치한다. 한 대만 고르면 행 메뉴와 같은 경로·알림이다. Android 기기 목록도 같은 툴바·규칙이다(`AndroidDevices` Feature, 판정은 ABI·API). 다만 꺼진 기기는 켜지 않고 이유와 함께 건너뛴다(Android 행 설치와 같다. 첫 켜기가 수십 초~수 분이고 여러 대를 함께 켜면 메모리가 모자라기 쉽다) |
| 앱 실행 | 설치한 앱 실행, 딥링크 열기 | `Info.plist` 의 번들 ID 로 `simctl launch`, `simctl openurl <기기> <url>`. 스킴이 있는 링크는 모두 연다(Core `DeepLink`: 앞뒤 공백을 빼고 경로·쿼리의 공백·한글은 퍼센트 인코딩). 꺼진 기기는 켜고, Simulator 앱을 열어(켜진 기기도) 연다. 링크는 기기 안의 앱(Safari 등)이 열고 SimLauncher 는 내려받지 않는다 |
| 스크린샷 | 켜진 기기 행 "스크린샷" 으로 화면을 PNG 로 사진 폴더의 SimLauncher 폴더에 저장하고 Finder 에서 선택해 보이기 | `simctl io <기기> screenshot --type=png --mask=ignored` (실기기처럼 사각 전체 화면). 실행 전에 목록으로 켜짐을 확인한다(꺼진 기기에서 simctl 은 약 60초 기다린 뒤 실패한다). 꺼진·쓸 수 없는 기기는 버튼이 비활성이고 켜지 않는다. 파일 이름은 Core `ScreenshotFileName`(`<기기 이름> (<런타임 이름>) <날짜> <시각>.png`, 경로 구분자·`:`·제어 문자는 `-` 로, 맨 앞 `.` 도 `-` 로, 같은 이름이면 ` 2`…` 99`). `Workspace` Client 가 `~/Pictures/SimLauncher` 를 만들고 빈 파일을 독점 생성으로 예약해(덮어쓰지 않는다) 촬영이 그 파일에 쓰고, `NSWorkspace` 로 Finder 에서 선택해 보인다. 촬영이 실패하면 빈 예약 파일을 지우고(내용이 있는 파일은 지우지 않는다) 원인과 다음 할 일을 알린다. 같은 기기는 한 번에 하나만 찍고, 같은 기기의 앱 설치·링크 열기·녹화 중에도 찍는다. 사진 폴더는 권한 팝업이 없다. Android 기기도 켜진 기기 행 "스크린샷" 으로 같은 폴더·이름 규칙(런타임 자리는 `API <버전>`)으로 저장한다: `adb -s <serial> exec-out screencap -p` 의 PNG 출력을 예약 파일에 쓴다(화면이 꺼져 있으면 검은 화면이 저장된다, 실측. 앱 실행 중에도 찍는다, ARCHITECTURE §4 Android 앱 설치 행) |
| 녹화 | 켜진 기기 행 "녹화" 로 화면을 H.264 QuickTime(`.mov`)으로 동영상 폴더의 SimLauncher 폴더에 녹화하고, 행에 녹화 중 표시·경과 시간·"중지" 를 보이고, 중지하면 저장하고 Finder 에서 선택해 보이기 | `simctl io <기기> recordVideo --codec=h264 --mask=ignored --force <예약 파일>` (스크린샷과 같은 사각 전체 화면, 소리 없음). 시작은 stderr 의 `Recording started` 로 알고, 멈춤은 SIGINT 다(마무리 측정 0.03~1.54초). 허용 기기 규칙은 스크린샷과 같고(쓸 수 있고 켜진 기기만, 꺼진 기기는 켜지 않는다) 실행 전에 목록으로 켜짐을 확인한다(꺼진 기기에서 simctl 은 0바이트 파일을 남기고 성공한다). 파일 이름은 Core `RecordingFileName`(스크린샷과 같은 규칙, 확장자 `.mov`, 시각은 "녹화"를 누른 시각). `Workspace` Client 가 `~/Movies/SimLauncher` 를 만들고 빈 파일을 독점 생성으로 예약해 녹화가 `--force` 로 그 파일에 쓴다. 0바이트로 끝나면 실패로 보고 빈 예약 파일을 지우고, simctl 이 스스로 실패로 끝나도 화면이 담긴 파일은 지우지 않고 Finder 에서 보이며 중간에 끝났다고 알린다. 녹화는 기기 작업과 따로인 기기별 상태라 같은 기기의 앱 설치·링크 열기·스크린샷은 녹화 중에도 되고, 끄기·초기화·삭제는 "녹화를 먼저 멈추세요" 로 막는다. 여러 기기를 각자 녹화할 수 있다. simctl 은 기기가 꺼져도 끝나지 않으므로, 목록을 다시 읽을 때(새로 고침·다른 행 작업 뒤·기기 목록을 다시 열 때) 녹화 중인 기기가 켜져 있지 않으면 멈추고 저장한 뒤 "기기가 꺼져 녹화를 멈추고 저장했습니다" 를 알린다(폴링하지 않는다). 창을 닫거나 개발 환경 화면으로 가도 녹화는 계속된다. 녹화 중 앱을 끝내면 "녹화를 멈추고 저장한 뒤 종료할까요?" 를 묻고 "저장하고 종료" 면 저장한 뒤 끝낸다 (로그아웃 중이면 로그아웃이 취소되어 다시 로그아웃해야 한다). 멈춤이 늦어 SIGTERM 까지 가면(약 5 GB 넘는 녹화) 서비스 쪽 녹화가 이어지다 기기를 끌 때 같은 파일에 저장되므로 그렇게 안내하고 파일을 지우지 않는다. 같은 기기를 다른 도구가 녹화 중이면 그 이유를 알린다. 동영상 폴더는 권한 팝업이 없다 (배포 서명·공증 빌드로 확인). Android 기기도 켜진 기기 행 "녹화" 로 같은 표시·폴더에 H.264 mp4(`.mp4`, Core `RecordingContainer`)로 녹화한다: 기기 안 `/data/local/tmp` 에 `screenrecord` 로 쓰고(API 34 이상은 멈출 때까지, 33 이하는 기본 3분에 스스로 멈추고 저장한 뒤 그렇게 알린다), 중지하면 기기 안 `kill -2 <pid>` 로 마무리한 뒤(실측 0.27~0.82초) `adb pull` 로 예약 파일에 가져와 기기 파일을 지운다. 녹화 중 기기가 앱 밖에서 꺼지면 다시 읽기 때 멈추고, 파일이 기기 안에 있어 가져오지 못하므로 "기기가 꺼지거나 연결이 끊겨 녹화를 저장하지 못했습니다" 를 알린다(켜는 중으로 읽힌 때는 멈추지 않는다). Mac 에 쓰지 못한 녹화는 기기에 남겼다가, 앱이 남긴 기기 녹화 파일은 그 기기에서 다음 녹화를 시작할 때 지운다. 앱 종료 확인은 iOS·Android 어느 쪽이 녹화 중이어도 한 번 묻고 둘 다 저장한다 (`AndroidDevices` Feature, ARCHITECTURE §4 Android 앱 설치 행) |

## 빌드 카탈로그
특정 회사 인프라에 묶이지 않도록, 앱이 읽는 카탈로그 형식을 이 프로젝트의 공개 규격으로 정한다.
- 사용자가 설정 창에서 카탈로그 URL 을 하나 이상 등록한다. 회사 일괄 배포용으로 `defaults write com.zopandagom.simlauncher CatalogURLs -array "https://…/catalog.json"` 나 MDM 으로 미리 넣을 수 있다. 미리 넣은 값도 같은 사용자 설정 키라서 네트워크 규칙의 "사용자가 등록한 카탈로그"에 든다. MDM 구성 프로필로 키를 강제하면 목록 전체가 잠겨 앱에서 바꿀 수 없다 (관리자 안내: [CATALOG.md](CATALOG.md) 9절)
- `catalog.json` 은 `schemaVersion` 과 앱 → 버전(이름·브랜치·태그·빌드 번호·생성 시각) → 빌드 파일 URL(iOS 는 .app 을 담은 zip, Android 는 .apk)을 담고, schemaVersion 2 는 앱마다 `platform`(`ios`·`android`)을 둔다. 앱은 schemaVersion 1(모두 iOS 로 본다)·2 를 읽는다. 규격: [CATALOG.md](CATALOG.md) (schemaVersion 2)
- 레포에 예시 GitHub Actions 워크플로를 둔다 (`.github/workflows/sample-catalog.yml` "Sample Catalog", 손으로 실행): 샘플 iOS 앱(`Examples/SampleApp`)을 `make sample`(`xcodebuild -sdk iphonesimulator`) → zip, 샘플 Android 앱(`Examples/SampleAndroidApp`)을 Gradle(CI 에서만) → apk → 두 파일을 빌드 릴리스(태그 `sample-build-<run_id>`, prerelease)에 업로드 → 릴리스 목록에서 schemaVersion 2 `catalog.json` 을 처음부터 다시 만들어 검증(`make catalog-check`) → 고정 태그 `sample-catalog-v2` 릴리스에 업로드. 1.0.0 사용자를 위해 옛 v1 태그 `sample-catalog` 는 더 고치지 않고 남긴다 ([CATALOG.md](CATALOG.md) 11절)
- 첫 버전은 인증 없는 HTTPS URL 만 지원한다(사용자 이름·비밀번호가 든 주소는 거절하고, 서버의 인증 요구에도 응하지 않는다). 비공개 저장소(토큰 헤더 등) 인증은 후속
- 공개 레포의 GitHub Releases 는 누구나 받을 수 있다. 개발 중 확인은 샘플 앱 빌드로만 하고, 회사 앱 빌드는 각자 비공개 저장소에 둔다
- GitHub Releases 로 둘 때 고정 URL: 빌드만 두는 레포면 `https://github.com/<owner>/<repo>/releases/latest/download/catalog.json`, 이 레포처럼 앱 릴리스와 같은 레포에 두면 latest 를 앱 릴리스에 남기고 고정 태그 릴리스(`…/releases/download/sample-catalog-v2/catalog.json`. v1 은 `…/sample-catalog/catalog.json`)에 둔다 (파일당 2 GiB 미만, 릴리스당 파일 1000개, 전체 용량·트래픽 제한 없음). 버전 항목의 빌드 URL 은 절대 주소로 쓴다(상대 주소는 거절, CATALOG.md)

0~6단계는 끝났다 (1.0.0 게시, 2026-10-27). 7단계(Android 에뮬레이터)를 진행 중이고(7-A·7-B·7-C·7-D 머지, 7-E 진행 중), 7-A~7-F 를 PR 하나씩 머지한 뒤 1.1.0 을 낸다. 그다음 작업은 "이후" 행에서 고른다.

`simctl` 하위 명령은 모두 `Simulator` Client Impl 이 `Command` Client 로 실행한다 (ARCHITECTURE §4). "단계 목표 확인" 열은 단계가 이룰 결과이고, 각 단계 작업을 시작할 때 명령으로 판정할 수용 확인(CONVENTIONS §6)과 사용자의 수동 확인(CONVENTIONS §5 "수동 확인" 행)으로 나눠 작업 범위에 적는다.

업데이트 알림(이후)은 외부 의존성(Sparkle 등) 없이 구현한다 (ARCHITECTURE §4).

## 작업 진행 방식
1. 로드맵의 단계 목표와 "단계 목표 확인" 열을 확인 → 작업 단위로 쪼갠다.
2. `feat|fix|chore/<요약>` 브랜치 생성 (일정 표시 없이, CONVENTIONS §5).
3. Client 가 필요하면 **Interface 먼저** 설계(프로토콜 + 값 타입) → Fake → Feature Model + 테스트 → Impl 순서. Impl 없이도 Example 앱으로 화면을 확인할 수 있다.
4. 역할 단위로 작업 범위·수용 확인을 정하고 구현 → `/verify` → `/arch-review`. 새 상태·실패 경로가 생기는 구현과 그런 수정이 필요한 리뷰 지적은 팀으로 한다 (CONVENTIONS §6 "팀 구현"). 커밋은 사용자 지시로 `/micro-commit` (CONVENTIONS §5).
5. 사용자 지시로 `/pr` (마지막 커밋 검사(빌드에 영향이 있으면 lint·빌드·테스트) + 전체 `/arch-review` → PR 생성, 유형 라벨) → CI + Claude 리뷰 → 리뷰 반영 커밋도 `/pr` 로 push (CI 지적에 답) → 머지 전 확인 뒤 Merge commit 으로 머지 (CONVENTIONS §5 "리뷰 지적 처리").
6. 결정이 바뀌었으면 문서 갱신을 같은 PR 에 포함한다 (별도 커밋, type 은 CONVENTIONS §5 마이크로 커밋 표).

## 완료 기준 (Definition of Done)
- [ ] `/pr` 의 마지막 커밋 검사 PASS·SKIP, 필수 체크 `ci-result` 통과, 머지 전 확인 충족 (CONVENTIONS §5 "리뷰 지적 처리")
- [ ] CONVENTIONS §3 이 요구하는 테스트 (미뤘으면 그 보류 기록, CONVENTIONS §5 "리뷰 지적 처리")
- [ ] 해당하는 수동 확인(Example 앱 주요 상태, 배포 서명 빌드) 완료 (CONVENTIONS §5 표 "수동 확인" 행)
- [ ] 제품 약속(CONVENTIONS §4) 위반 없음

## 위험과 대응

| `xcrun simctl` 실행에는 App Sandbox 밖 동작이 필요해 Mac App Store 배포가 어려움 | Developer ID 서명·공증 배포 (ARCHITECTURE §4) |
| Apple 실리콘 Mac 에서는 arm64 slice 가 없는 시뮬레이터 빌드가 설치되지 않음 (`simctl install` 이 거절, Xcode 27.1·iOS 27.0 에서 확인) | 설치 전에 실행 파일 아키텍처를 검사해 이유를 보여 준다 (2단계) |
| 공개 레포라 외부 PR 이 워크플로를 돌리거나 Releases 의 빌드가 누구에게나 공개됨 | PR 트리거는 `pull_request` 만 쓰고 `pull_request_target` 은 쓰지 않는다(fork PR 은 시크릿 없음), 외부 기여자 워크플로는 승인 후 실행. Releases 에 올리는 iOS 앱 빌드는 샘플 앱만 (회사 앱 빌드는 각자 비공개 저장소에) |
| 입력받은 URL·zip 이 신뢰할 수 없는 내용일 수 있음 | HTTPS 만 허용(리다이렉트 포함), 압축 해제 경로가 대상 폴더를 벗어나지 않는지 검사 (CONVENTIONS §4) |
| Android SDK 가 크다 (받기 약 2.5 GB, 설치 후 약 7 GB, 설치 중 최대 약 9.1 GB) | 설치는 사용자가 누를 때만 하고, 동의 시트에 받을 크기와 설치 후 어림 크기(볼륨별)를 보인다. 받기 전에 두 볼륨의 여유를 어림으로 비교하고, 패키지마다 받은 zip 을 풀자마자 지우며, 저장 공간이 모자라면 필요한 양과 함께 알린다 |
| Android Studio 와 SDK 폴더를 함께 쓴다 (package.xml·licenses 를 쓰지 않아 Studio 가 다시 받거나 동의를 다시 물을 수 있음, 동시 설치) | 없는 구성 요소만 설치하고 이미 있는 폴더는 덮어쓰지 않는다(`RENAME_EXCL`). 상태 판정은 실행 파일·이미지 파일만 본다. 동의는 앱 설정에만 기록하고 Studio 쪽 동의가 따로 필요하다고 안내한다 |
| Android 기기(AVD)가 크고 첫 켜기가 길다 (첫 사용 뒤 약 5 GB, 콜드 부팅 30~60초, 두 대를 함께 처음 켜면 2~3배) | 켜기를 10분까지 기다리고 켜는 중인 행에 "처음 켤 때는 몇 분 걸릴 수 있다" 를 보인다. 저장 공간이 모자라 에뮬레이터가 끝나면 저장 공간 확인과 초기화를 안내한다 (앱이 미리 공간을 비교하지는 않는다). 여러 기기 설치는 꺼진 기기를 켜지 않는다 (기기 한 대만 켠 16 GB Mac 에서도 swap 13.3 GB 중 12.97 GB 를 썼다, 2026-10-30 실측. 필요하면 "선택한 기기 켜기" 를 먼저 누른다) |
| 켜는 중에 끄면 다음 켜기가 끝나지 않을 수 있다 (첫 부팅 도중 끄면 300초 넘게 완료되지 않음, 실측) | 앱이 켜는 중인 기기는 끄기를 막고, 앱 밖에서 켜는 중이거나 켜기 대기가 시간 초과된 기기를 끈 뒤 켜지지 않으면 초기화를 안내한다 (초기화로 복구됨, 실측) |
| Android apk 의 이전 버전 설치(다운그레이드)는 데이터를 남긴 채 버전만 바꾼다 (앱이 새 버전이 남긴 데이터 형식을 읽지 못할 수 있다) | iOS 와 같이 버전과 관계없이 덮어쓰는 동작으로 두고(`adb install -d`), 기기가 거절하면(user 빌드 이미지에서 debuggable 이 아닌 앱) 앱을 지운 뒤 다시 설치하라고 안내한다 |

| Android 에뮬레이터가 켤 때마다 스스로 Google 서버(`dl.google.com`)에 접속한다 (업데이트 확인·기능 설정, 끄는 옵션 없음) | 네트워크 약속에 적고(ARCHITECTURE §4 네트워크 행), 끌 수 있는 사용 통계·크래시 보고·adb mDNS 는 끈다 |
